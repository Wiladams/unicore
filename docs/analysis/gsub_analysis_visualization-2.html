What changed for workload selection

  • GSUB Single remains the largest operation class (89,321), while ChainContext is also substantial (24,310).
  • Filter behavior is not marginal: 28,960 compiled lookups carry filtering semantics; IgnoreMarks dominates at 15,470, with 9,345 mark-filtering-set lookups.
  • Context candidate-dispatch pressure is now directly visible: first-set fanout and same-prefix fanout are distinct dimensions, so workloads can separate broad first-glyph competition from deeper prefix competition.
  • PairPos now has a direct same-first-glyph stress dimension via max second-glyph fanout, which is much better than a generic pair miss for evaluating explicit-pair indexing.
  • Class PairPos density and nonzero-row fanout support workloads for dense rows, sparse rows, populated zero-cell misses, and guaranteed nonzero hits.
  • The analysis is now sufficient for workload selection; actual glyph sequences should be discovered by the workload generator from the selected IR rather than emitted by the census.
  • Compiler census analyzed 3,520 of 3,807 faces, with 104 GSUB and 101 GPOS lookup compile failures.
